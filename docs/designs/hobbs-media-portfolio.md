## Problem Statement

Sam (Hobbs Media Co.) shoots photography, video, and aerial drone footage for real
estate agents in the Seattle / Puget Sound area. He needs a site he can text, email,
or hand over on his phone to an agent he just met. It has to look like someone cared.
Jonny is building it as freelance work for a friend, wants to try Next.js on a host
other than AWS Amplify, and wants Sam to choose between real options asynchronously
over text rather than on a call.

## What Makes This Cool

- **The reel is the site.** Sam's footage plays the instant the page opens, on a
  phone, before any navigation. The hero is a full-bleed muted aerial loop with a
  monogram, the wordmark in wide-tracked caps, and a three-line plaque of trust
  signals, modeled on cabanetortin.com.
- **Scroll dims the reel to black.** Jonny's twist on the reference: the first scroll
  gesture fades the footage toward black and the mark lifts away. On the home page
  that is the hinge into Sam's sections. On share links it reveals contact and stops.
- **The texted link is the referral channel.** Agents hire on referrals and trust
  signals, not artistry (research below). Per-agent and per-property links carry a
  personalized plaque and a rich iMessage preview, so a forwarded link reads as a
  calling card, not a portfolio.
- **Scroll-through work that just plays.** The one thing Sam explicitly asked for:
  a vertical stack of clips that autoplay as you scroll, no play button. Done right
  (short encoded loops, poster frames, viewport-triggered playback) it is smooth
  on cellular, which his Lovable version is not.

## Recommended Approach: B, "The Referral Artifact", with the merged structure

**Stack.** Next.js (App Router), TypeScript, Tailwind. Vercel Hobby. Video as
static files in `public/` served from Vercel's CDN (Range requests supported, which
iOS requires). No CMS, no database, no auth. New repo (not this playground). Commit
pipeline outputs only, never source footage; no Git LFS (Vercel builds skip it).

**Routes.** During review every route lives under a theme segment,
`app/[theme]/...`, with `generateStaticParams` over the four themes. That keeps
the whole site statically generated, gives Sam four distinct URLs
(`/dark`, `/hobbs/for/jessica`), lets OG images read the theme from params, and
leaves no `?theme=` code path to strip at launch. At launch the chosen theme
becomes the root and the segment is removed (or 301'd).
- `/[theme]` home: Hero → dim-to-black → What I do → Selected work → About → Get in touch.
- `/[theme]/for/[agent]` calling card, plaque personalized ("PREPARED FOR JESSICA · WINDERMERE").
- `/[theme]/p/[slug]` calling card for one property, optional reel override, plaque
  names the property (address-free unless Sam wants it) and the agent it was
  delivered for. Route exists from day one; ships publicly when the first property
  film lands.
- Share links always render the cinematic two-beat hero, regardless of theme.
  `hobbs` only changes the home page hero.
- Unknown agent or property slug → `notFound()` (404), never a redirect.
- Every route renders its own OpenGraph image via `opengraph-image.tsx` +
  `ImageResponse` (poster frame + mark + one plaque line). Fonts loaded as
  ArrayBuffers. The poster is read from disk at build time
  (`fs.readFile(path.join(process.cwd(), "public/clips", id + ".jpg"))`) and passed
  as a `data:` URL, because with `generateStaticParams` the OG route renders during
  `next build` when nothing is serving `/clips/*` yet. `metadataBase` is set from
  the site URL (or `VERCEL_URL` on previews) for the emitted `og:image` URL only.
  Budget half a day, not an hour. iMessage caches a link preview per URL
  essentially forever, so `/for/` links go out only after the OG image is final.
- Metadata per route: `title`, `description`; `robots: { index: false }` on
  `/for/*` and `/p/*` (a "PREPARED FOR JESSICA" page must never be indexed).
  `robots.ts` allows the home page only. No sitemap for a one-URL site.

**Content model.** One source of truth for clips is the pipeline manifest;
everything else references it by id.
- `clips/manifest.json` (input to the pipeline): `id`, `source`, `in`, `out`,
  `speed`, `focal` (x, y as 0..1 for `object-position`), `loop: "xfade" |
  "pingpong" | "none"` (xfade for slow drifts, pingpong for one-way moves like the
  4 s city rise, none = play once and hold the last frame), optional `maxrate`
  override per rung. Outputs land in `public/clips/<id>.{1080,720}.mp4`,
  `public/clips/<id>.jpg` (720 w, stack overlays and phone hero) and
  `public/clips/<id>.poster.1920.jpg` (from the 1080 encode, for the `hobbs`
  desktop still hero and the OG image source). The script also emits a typed
  index, `content/clips.generated.ts` (`id → { focal, loop, duration }`), which
  is how components read `focal` and `loop` by id. The `loop` attribute on any
  `<video>` is set only when the clip's mode is not `none`.
- `content/site.ts`: brand name, wordmark text, `heroClip: clipId` (the home hero
  and every share link play this unless a property overrides it),
  `heroImage?: path` (a Sam-supplied photo for the `hobbs` still hero; falls back
  to the hero clip's 1920 poster), plaque lines, contact (`sms:`, `mailto:`,
  instagram), services (3), about copy, stats. Any unconfirmed value is wrapped
  `todo("Nashville, TN")`; `todo()` returns its argument normally and throws only
  when `NODE_ENV === "production" && !process.env.SITE_PASSWORD`, so `next dev`
  and CI typechecks are unaffected and `.env.local` needs no password. While the
  site is gated the build passes; launch is literally "unset the password." One
  signal enforces Premise 7 and "no placeholder facts" by the build, not by memory.
- `content/work.ts`: `work[]` = `{ slug, title, subtitle, tag: "drone" | "videography"
  | "photography", media: { clip: id } | { image: path } }`. Photography entries
  use `image`, live in `public/work/`, and render as a static frame via
  `next/image` with `sizes="100vw"`. (Sam has sent no photos yet; the type exists,
  entries wait.)
- `content/properties.ts`: `properties[]` = `{ slug, title, subtitle, reel?: clipId,
  agent?: agentSlug, address?: string }`. Address renders only if present.
- `content/agents.ts`: `agents[]` = `{ slug, displayName, brokerage? }`.
- `content/themes.ts`: tokens per theme (palette, font families, hero variant,
  accent). Fonts: `hobbs` = Instrument Serif (Google Fonts) + Manrope (Google
  Fonts). Cinematic themes = Satoshi (Fontshare; confirm the license covers
  server-rendered OG images before launch, else fall back to a Google Fonts
  geometric such as Outfit).

**Mark.** The wordmark "Hobbs Media Co." is the mark (Sam's direction, see open
question 3). Two-tone: brand word in the theme's primary type color, "Media Co."
in a muted secondary. In the cinematic hero it sits where the monogram was in the
renders, centered above the plaque; in `hobbs` it stays top-left as on his site.

**Themes (four links to Sam).** Jonny chose to build all three cinematic palettes
plus Sam's own; the reviewer noted `twilight` is close to `dark` plus an accent.
Accepted: themes are token sets, so the fourth costs little.
- `hobbs`: his Lovable design rebuilt faithfully. Editorial serif headlines,
  tracked-caps labels, humanist sans body, cream and near-black, his hero (still,
  headline, two CTAs). "You designed this, I made it work."
- `dark`: our hero, his sections. Off-white type on near-black. A CSS overlay tint
  gives the cool dusk feel; the footage itself is untouched.
- `light`: our hero, his sections. Warm cream, charcoal type, geometric sans,
  never cold gray.
- `twilight`: our hero, his sections. Cream type, single brass accent token on the mark.
Hero treatment is the only structural difference between `hobbs` and the others.
Mixing (his serif with our hero) is a config change.

**Hero.** Fixed full-viewport (`100svh`) `<video muted autoplay playsInline loop
preload="auto" poster>` in a `200svh` scroll container. The server-rendered `src`
is always the 720 rung (mobile first, no-JS default). A tiny inline `<script>`
placed immediately after the `<video>` runs during parse, before hydration and
before meaningful bytes arrive, and sets `src` to the 1080 rung when
`matchMedia("(min-width: 1024px)")` matches. A hydration-time effect would run
too late on broadband and desktop would play 720 upscaled forever. Beat 1 at top:
mark, wordmark, plaque, SCROLL cue. A passive scroll listener +
`requestAnimationFrame` maps scroll progress 0→1 to overlay opacity 0→0.86 and a
small upward translate on the mark (starting values; tuned by eye). On the home
page the sections take over at progress 1: they have an opaque background and a
stacking context above the fixed video so nothing peeks through; the hero pauses
when covered, releases its `src` only when more than two viewports away, and
re-attaches when scrolled back within one viewport (same rule as the stack). On
share links, contact fades in with one quiet link to the work (`/[theme]#work`)
and the page ends. `prefers-reduced-motion`: poster only, no dim animation, stack
shows posters. If `play()` rejects (iOS Low Power Mode blocks even muted
autoplay), the poster is the hero and nothing breaks. Plaque text sits on a
subtle bottom-weighted gradient so contrast holds over bright water and sunset
frames. Decorative videos get `aria-hidden`; the page's tab order runs mark-free:
wordmark, plaque, contact links, sections.

**Selected work.** Vertical stack of full-width clips in Sam's layout (serif title
+ tracked-caps subtitle + outlined tag overlay). Stack videos never carry the
`autoplay` attribute (iOS would auto-resume them and fight the observer). Each
starts with `preload="none"`, no `src`, and no `poster` attribute (video posters
load eagerly); the poster is an `<img loading="lazy">` overlay, 720 px wide, JPEG
quality ~75. A single controller assigns `src` when a clip is within one viewport
of view, releases it (`removeAttribute("src"); load()`) when it is more than two
viewports away, and plays only the clip whose center is closest to the viewport
center, pausing the rest. That keeps iOS Safari at one active decoder plus the paused hero. If
`play()` rejects, a small tap-to-play affordance appears on that poster. Tap opens
nothing else in v1 (no lightbox); the loop is the work.

**Footage pipeline (the content path).** A script (`scripts/encode.ts`, ffmpeg)
reads `clips/manifest.json` and produces per clip, from one 16:9 source:
- `<id>.1080.mp4` for desktop heroes: H.264 `-profile:v high -level 4.0
  -pix_fmt yuv420p`, CRF 23, `-maxrate 4M -bufsize 8M`, no audio track (`-an`),
  `-movflags +faststart`. Lands around 4 MB for a 10 s loop.
- `<id>.720.mp4` for the stack and for phone heroes (Chrome ignores `media` on
  `<source>`, so the rung is chosen in JS as above): same settings, 720p, CRF 24
  to 26, `-maxrate 1.2M -bufsize 2.4M`. Around 1.5 MB.
- `<id>.jpg` poster taken from frame 0 of the encoded output, 720 px wide.
- Loop seam per the manifest `loop` field. `xfade`: the 0.5 s overlap is taken
  from inside `[in, out]` (so `in`/`out` stay the exact range Jonny picked and the
  loop is 0.5 s shorter), assembled body-first with the blend appended at the end
  so frame 0 is a clean source frame and matches the poster. Use it for slow
  drifts (sunsets, coastline, orbit at its slowest point). `pingpong` for one-way
  moves (the city rise). Pick in/out points where motion is slowest; a crossfade
  across a fast pan double-images.
No 9:16 encode. Phone framing is CSS: `object-fit: cover; object-position:
<focal>` from the manifest, which gives the same crop from the single encode.
Targets: 6 to 12 second loops. Water shimmer and sunset gradients are the hard case
for H.264; if a clip bands, raise its `maxrate` in the manifest rather than
lowering CRF globally. Adding or swapping a clip is one manifest entry plus a
rerun. When Sam sends a re-export of the same source, the manifest does not
change. The 58 s yacht clip becomes two entries that skip the camera
readjustment. This replaces CapCut entirely; no manual editing.

**Contact.** `sms:` and `mailto:` links, Instagram link. No form in v1 (a form is a
spam surface and agents text). Hours and service area only if Sam confirms them.

**Preview gate.** *SUPERSEDED by eng review decision 7A (2026-09-21): there is no
password gate. See "Engineering Review Amendments" below. The paragraph is kept
for the record.* Vercel Password Protection is a paid add-on and "Vercel
Authentication" would require Sam to have a Vercel login, so the gate is the
Next.js edge middleware (whatever the current release names the file) serving a
shared-password page that sets a cookie. Its matcher is a path-prefix match. It
exempts `/_next/*`, `/favicon*`, `/clips/*`, and every `opengraph-image` route.
Link-preview fetchers send no cookies and read the page's `<meta og:*>` tags
before they ever see the image URL, so the middleware also serves the page
ungated to known preview user agents (`facebookexternalhit`, `Facebot`,
`Twitterbot`, `Slackbot`, `WhatsApp`, `LinkedInBot`; iMessage's fetcher
identifies as `facebookexternalhit/1.1 Facebot Twitterbot/1.0`, there is no
"iMessage" token). A spoofed UA
can see a gated portfolio preview; acceptable for this site. Every gated response
carries `X-Robots-Tag: noindex` so the password page itself is never indexed.

**Hosting terms.** Vercel's Hobby plan prohibits commercial use, and a client's

- **2A Hero island:** the hero `<video>` and its inline script are emitted as raw
  HTML via `dangerouslySetInnerHTML` from a server component; React never
  reconciles the subtree. A wrapper `ref` exposes the element to the controller.
  One helper (`lib/heroIsland.ts`) templates the markup and is unit-tested,
  including escaping of ids and URLs.
- **3A Gate cookie:** superseded by 7A (no gate).
- **7A No password gate:** review links are Vercel preview URLs (unguessable);
  every route is `noindex` while `SITE_STAGE=review`; `proxy.ts` is not needed.
  Sam is told in the text that review links carry placeholder facts and should
  not be forwarded to agents until confirmed.
- **T1 Guard fails closed:** `SITE_STAGE` must be exactly `review` or `live`;
  anything else fails the build. When `VERCEL_ENV=production`, the build also
  requires `live`. `.env.example` ships `SITE_STAGE=review`.
- **T2 Clip approval:** manifest entries carry `approved: boolean` (default
  false). The encode script and the launch guard refuse to ship an unapproved
  clip when `SITE_STAGE=live`. In review, unapproved clips render with a small
  corner tag so Sam sees what is pending.
- **T7 Vercel deployment protection:** disable Vercel Authentication for preview
  deployments on day one. A Playwright check runs logged out against the deployed
  preview URL and asserts HTML plus a 200 `image/png` from the OG route.
- **4A Encode script:** zod-validated manifest; preflight ffmpeg/ffprobe on PATH
  (fail with the Homebrew install line), source exists, `in < out <= duration`,
  `speed > 0`, `focal` in 0..1, `loop` enum, unique ids, named errors. Sidecar
  hash of (source hash, entry JSON, encoder settings) skips unchanged clips.
  Outputs written to a temp path then renamed. Stale outputs with no matching
  sidecar are pruned.
- **8A Hashed outputs:** outputs are `<id>.<hash8>.1080.mp4`,
  `<id>.<hash8>.720.mp4`, `<id>.<hash8>.jpg`, `<id>.<hash8>.poster.1920.jpg`,
  served with `Cache-Control: public, max-age=31536000, immutable` via
  `next.config` headers. The generated index carries the hashed names; no
  component builds a clip URL by hand.
- **5A VideoBudget:** one page-level controller registers every `<video>`
  including the hero island. Policy: attach `src` within one viewport, release
  beyond two, only the clip closest to viewport center plays, hero has priority
  while scroll progress < 1. Handles `play()` rejection (tap affordance),
  `prefers-reduced-motion` (posters only), `visibilitychange` (pause all),
  unregister on unmount.
- **T3 Island init on client navigation:** the island renders
  `data-hero-init="0"`; the inline script sets `1` after running. On register,
  VideoBudget performs the same rung choice and poster-then-play sequence when

- **T4 No `autoplay` attribute:** anywhere. The inline script (or the controller

- **9A Poster first:** `<link rel="preload" as="image" fetchpriority="high">` for

- **10A Theme fonts:** one `next/font` module per theme (`fonts/hobbs.ts`,
